# CLAUDE.md

Internal RAG chat app on AWS serverless. Design lives in `docs/architecture.md` (Japanese) and `docs/adr/` — read the relevant sections before making design decisions.

- `apps/frontend/` — Vite + React + TypeScript SPA
- `apps/backend/` — FastAPI, Python 3.12, `uv`
- `cdk/` — AWS CDK (TypeScript)

`make lint` / `make test` run all checks. Docker only builds the Lambda images (see ADR-0003); there is no local Lambda emulation. All FastAPI routes live under `/api`; the Vite dev server proxies `/api` to `:8000`, so there is no CORS middleware.

## Hard constraints

- Zero fixed cost: no VPC, NAT, ECS/EC2/Aurora, or Provisioned Concurrency.
- Only chat-fn loads LangChain libraries.
- Files go from the SPA to S3 via presigned URLs, never through Lambda.
- The backend only verifies Cognito JWTs; never handle passwords or issue tokens.
- CI workflows never run `cdk deploy`; infrastructure changes are applied manually.

## Code style

- TypeScript: no nested ternaries or nested arrow functions; name every branch of a finite set (unions, enums, states); prefer early returns.
- Python: `dataclass`/`NamedTuple` for internal models, `TypedDict` for JSON; fully parameterize container types; don't reassign parameters.
- Comments only for what the code cannot say: constraints, cross-module contracts, surprising framework behavior, intentional deviations. Keep them to 1–3 lines. Python function docstrings are one line and only when the signature is not enough; no `Args:`/`Returns:` sections.

## Japanese writing

- Restructure rather than translate English sentence by sentence; follow the terminology already used in the repository.
- Make the relationship between adjacent sentences explicit with a connector (そのため, しかし, ただし, 一方で) or by restructuring, without opening every sentence with one.
- After drafting, reread the Japanese on its own.

## Local drafts

`docs/issues/`, `docs/plans/`, and `docs/PRmessages/` are gitignored drafts. Never commit them or cite their paths in commits, PRs, or issues.

## Notes

- Diagrams in `README.md` and `docs/architecture.md` are SVGs exported from `docs/diagrams/blueprint.drawio`. Edit the drawio file, never the SVGs; the user re-exports them.
